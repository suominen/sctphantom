SCTPhantom (CVE-2026-64564) is a use-after-free in the Linux kernel SCTP
stack. sctp_process_asconf() caches the transport an ASCONF chunk is
processed against in asconf->transport. An ASCONF carrying, in order,
[Address Parameter L][DEL-IP L][DEL-IP 0.0.0.0] — where L differs from the
packet source — makes the DEL-IP for L pass the D8 source-address check and
call sctp_assoc_rm_peer() on the still-cached transport, freeing it
(RCU-deferred); the wildcard DEL-IP then reuses the dangling
asconf->transport in sctp_assoc_set_primary() and
sctp_assoc_del_nonprimary_peers(), planting freed memory into
asoc->peer.primary_path / active_path. Impact: kernel oops/panic (DoS) and,
per the discoverers, local privilege escalation and container-to-host
escape; the chunk is processed in the receive path, so a remote SCTP peer
on an established association with ADD-IP negotiated can trigger it. The
fix is 9b2854f86f0b (sctp: don't free the ASCONF's own transport in DEL-IP
processing), first released in v7.2-rc5.

CRITICAL — this is an ANCIENT bug, not a regression. The introducing commit
42e30bf3463c is v2.6.25 (2008), so EVERY maintained SCTP-capable kernel is
in-window. There is NO "predates the introducing commit / Not affected"
case. A row is Fixed ONLY by carrying the 9b2854f86f0b backport; every
other in-support kernel is Vulnerable. Do not mark any kernel row
":heavy_minus_sign: Not affected" on age grounds.

Reachability (prose, NOT a verdict axis): the `sctp` module must be in use
(on most distros it autoloads on first SCTP socket; Rocky/RHEL 8/9/10 alike
ship sctp.ko in kernel-modules-extra with a default `blacklist sctp` that
suppresses autoload), an association established with the ADD-IP/ASCONF
extension, and a valid AUTH chunk. Both ADD-IP and AUTH can be enabled
per-socket (SCTP_ASCONF_SUPPORTED / SCTP_AUTH_SUPPORTED, no privilege, no
CAP_NET_ADMIN), so the addip_enable / addip_noauth_enable sysctls bound only
the remote surface, not the local privesc/container path — a local attacker
enables both on its own socket and authenticates its own ASCONF.
